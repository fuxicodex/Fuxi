# FuXi Cryptography Standard

*Last updated: 2026-08-23 · Version 1.0 · Layer: L2 Standard*

This standard sets the principles and requirements for FuXi's use of
cryptography in transit and at rest. **Honesty principle**: this document claims
only verifiable implementations and does not fabricate specific algorithm
details; unknown details are marked "subject to actual product implementation"
to avoid overclaiming.

---

## 1. Cryptographic objectives

Provide technical guarantees of **confidentiality, integrity, and authenticity**
across both transit and storage.

---

## 2. Transport security

| Scenario | Requirement |
|---|---|
| Communication with model providers (BYOK) | Uses the provider-required encrypted transport (typically TLS), negotiated between provider and user |
| Official install/update downloads | Downloaded over HTTPS (TLS) |
| Update integrity | SHA-256 checksum verified against the manifest after download |

> Note: transport encryption with model providers is implemented by **that
> provider**; FuXi follows its standard client behavior and does not "invent"
> encryption protocols.

---

## 3. Storage security

| Data | Requirement |
|---|---|
| Local credentials (config.yaml) | Stored on the user's device; protected by filesystem permissions; **recommend** enabling disk/filesystem encryption |
| Local sessions/memory/audit | Same, protected by the user's device security policy |

> **Honesty statement**: FuXi stores credentials and data locally under
> `~/.fuxi/` and does not upload them. Whether local files are additionally
> encrypted, and with which algorithm, is subject to actual product
> implementation; this Program does **not** fabricate undisclosed encryption
> details and recommends OS-provided encryption (e.g., FileVault, BitLocker,
> LUKS) to strengthen local protection.

---

## 4. Hashing and verification

- Update-package integrity uses **SHA-256** checksums (publicly stated in the
  README).
- Other hashing uses are subject to actual product implementation.

---

## 5. Keys and key material

- API keys / OAuth tokens are generated by the user or the provider; FuXi does
  **not** generate or host users' provider keys.
- Keys are stored locally only, never copied or uploaded.

---

## 6. Compliance and evolution

- Adopt widely accepted, public standard algorithms; no "home-grown" encryption.
- Retire weak algorithms as standards evolve, via product updates.

---

*This standard ensures the use of cryptography is honest, transparent, and
verifiable.*
