# FuXi 认证标准

**Authentication Standard**

*最后更新：2026-08-23 · 版本 1.0 · 层级：L2 标准*

本标准规定 FuXi 如何认证用户身份、保护凭据，以及访问模型提供商时的认证
机制。

---

## 1. 认证路径

FuXi 支持两种认证路径：

| 路径 | 机制 | 用途 |
|---|---|---|
| 自带密钥（BYOK） | API Key / 环境变量 / 本地配置 | 认证到用户选择的提供商 |
| FuXi 账号（可选） | OAuth 登录（`fuxi login` / `setup-token`） | 开通 FuXi 托管模型 |

---

## 2. 凭据管理要求

1. **本地存储**：API Key 存于 `~/.fuxi/config.yaml` 或环境变量，不上传。
2. **最小暴露**：凭据不写入日志、错误信息、截图或 issue/PR。
3. **文件权限**：建议 `config.yaml` 设为仅用户可读（如 `chmod 600`）。
4. **环境变量**：`FUXI_API_KEY` 等可替代配置文件，便于 CI 场景。

---

## 3. OAuth 令牌（可选登录）

- `fuxi login`：浏览器授权，令牌仅用于认证与开通托管模型。
- `fuxi setup-token`：打印 token 供 `FUXI_OAUTH_TOKEN` 在无交互/CI 环境使用。
- 令牌按最小权限签发，用户可随时退出/撤回。

---

## 4. 对提供商的认证

- BYOK 模式下，FuXi 以标准客户端方式向提供商出示用户的密钥，完成认证。
- 认证安全（TLS、密钥轮换）遵循提供商标准。

---

## 5. 会话与本地身份

- 本地会话数据与用户设备账号/文件权限绑定，无额外网络身份要求。
- 无账号即可使用核心功能，不强制注册。

---

## 6. 责任

- **FuXi**：实现安全的凭据读取与 OAuth 流程，不泄露、不上传凭据。
- **用户**：妥善保管密钥，设置本地权限，及时轮换泄露的密钥。

---

*本标准确保身份认证与凭据处理安全、透明。*
