# FuXi 安全白皮书

**Security Whitepaper**

*最后更新：2026-08-23 · 版本 1.0*

本白皮书说明 FuXi 的安全架构与威胁模型，面向全球用户与安全研究人员。
FuXi 会执行 shell 命令、在本地存储提供商凭据、并通过网络自更新 —— 因此
我们欢迎并感谢安全报告。**FuXi 本质安全、保护用户**，这一目标通过以下
技术设计落地，而非空谈。

---

## 1. 核心安全设计原则

FuXi 从五个层面保证安全：

1. **本地优先** —— 代码、配置、凭据、会话默认留在你的设备上，减少攻击面。
2. **默认不信任外部输入** —— 命令、文件、MCP 内容在执行前均经过校验。
3. **显式权限** —— 敏感操作需你批准，不隐式越权。
4. **可验证性** —— 更新经校验和验证，行为可通过审计日志追溯。
5. **最小权限** —— 只处理完成任务所必需的最小能力。

---

## 2. 威胁模型

我们明确识别并应对以下威胁：

| 威胁 | FuXi 的应对 |
|---|---|
| 恶意/危险的 shell 命令 | 命令在执行前经过 **AST 安全分类器** + 规则集过滤 |
| 未授权访问本地凭据 | API Key 仅存于本地 `~/.fuxi/`，不上传；权限受文件系统保护 |
| 供应链攻击（篡改二进制） | `fuxi update` 做 SHA-256 校验和验证，原子替换 |
| 模型提供商侧泄露 | 你自带密钥，内容直连你选择的提供商；不使用账号则不经 FuXi |
| 恶意 MCP / 插件 | 仅加载你显式配置的服务器；默认不启用 |

---

## 3. 命令安全

FuXi 可以执行 shell 命令（`bash` / PowerShell）。为保证这一能力不被滥用：

- **AST 安全分类器**：命令在执行前被解析为抽象语法树，由分类器判断其安全
  级别。
- **规则集**：额外的策略规则拦截危险模式。
- **权限模式**：`default` / `plan` / `bypassPermissions` 由你选择；`--auto`
  仅自动批准经分类器判定为安全的操作，且带熔断机制。
- **审计日志**：所有执行动作均可追溯、可审阅。

> ⚠️ `--dangerously-skip-permissions` 会跳过全部权限检查，仅建议在完全可信、
> 隔离的环境中自行承担风险使用。

---

## 4. 凭据与密钥处理

- **存储位置**：API Key、OAuth token 等凭据保存在本地 `~/.fuxi/config.yaml`
  或环境变量中。
- **不上传**：FuXi 不把你的密钥复制或上传到任何 FuXi 服务器。
- **自带密钥（BYOK）**：密钥只用于对你配置的提供商发起请求，直接往返于你
  与提供商之间。
- **建议**：为凭据文件设置适当的文件系统权限；在共享截图/日志前脱敏密钥。
  请勿在 issue、PR 或附件中粘贴密钥。

---

## 5. 更新安全

- FuXi 会后台检查新版本（可通过 `--no-update-notifier` 或
  `NO_UPDATE_NOTIFIER=1` 关闭）。
- `fuxi update` 下载目标版本后，会**对照已发布的 manifest 校验 SHA-256**，
  验证通过后才**原子性地**替换正在运行的二进制，杜绝被篡改或安装到一半的
  中间状态。
- 安装脚本来自 `https://downloads.fuxicode.com`，请只从官方渠道安装。

---

## 6. 受支持版本

仅最新版本获得积极维护。请保持版本最新，并在报告前用 `fuxi --version`
确认受影响版本。

---

## 7. 报告漏洞

请通过 GitHub 的
[安全通告（Security Advisories）](https://github.com/fuxicodex/Fuxi/security/advisories/new)
**私下**报告疑似漏洞。**请勿**就安全问题公开提交 issue。

报告请包含：

- FuXi 版本（`fuxi --version`）及安装方式；
- 操作系统与 shell；
- 最小复现步骤或概念验证；
- 你评估的影响范围。

**处理预期**：我们会尽最大努力审查，通常数日内给初次回复，并随进展更新。
若报告被采纳，我们会争取在细节公开前发布修复，并与你协调披露时间；一般
约定在确认与公开披露之间预留最长 90 天窗口，如修复更快发布可缩短。

感谢你帮助守护 FuXi 用户的安全。
