## 1. 事件响应

### 1.1 定义与严重级别

**安全/隐私事件**是指任何实际发生或疑似发生的、损害用户数据、系统或产品
机密性、完整性或可用性的事件。

| 级别 | 定义 | 示例 |
|---|---|---|
| **P0 严重** | 凭据泄露、远程代码执行、大规模数据泄露 | 更新被篡改、凭据被上传 |
| **P1 高** | 权限模型被绕过、命令分类器失效 | 危险命令绕过护栏 |
| **P2 中** | 导致非预期访问或数据暴露的缺陷 | 日志泄露非敏感信息 |
| **P3 低** | 轻微问题，无安全影响 | 文档错误 |

### 1.2 响应目标（尽力而为）

> 下表中的时间窗口是**尽力而为的目标，而非合同保证**；均从事件被确认的
> 那一刻起算。

| 级别 | 发现 → 响应 | 遏制 | 修复 | 通知 |
|---|---|---|---|---|
| P0 严重 | ≤ 2 小时 | ≤ 1 个工作日 | 在披露前发布修复 | 及时通知受影响用户 |
| P1 高 | ≤ 1 个工作日 | ≤ 2 个工作日 | 按优先级，下个发布窗口 | 按影响范围通知 |
| P2 中 | ≤ 3 个工作日 | 按计划 | 下个版本 | 视情况通知 |
| P3 低 | 下个迭代 | — | 随迭代 | 视情况通知 |

由于各司法辖区的泄露通知时限不同（GDPR 72 小时、新加坡 3 天、澳大利亚
"在切实可行范围内尽快"），我们在内部采用**最严格**的目标，以确保每个法域
的要求都得到满足。

### 1.3 响应阶段

**准备 → 发现 → 遏制 → 根除 → 恢复 → 复盘。**

1. **准备（持续进行）** —— 维护响应人员名册与联系方式、受影响版本清单和私下
   报告渠道；定期开展演练。
2. **发现** —— 接收报告（私下安全通告、对服务端基础设施的内部监控、社区）；
   确认真实性；收集 `fuxi --version`、操作系统、shell 与复现步骤；评定严重
   级别。
3. **遏制** —— P0：立即评估影响，必要时暂停受影响的发行/更新，并通知受影响
   用户，且在两小时内启动。P1：在一个工作日内提供临时缓解措施。P2/P3：记录
   并安排修复。
4. **根除** —— 定位根本原因；开发修复并运行回归测试；验证更新包（SHA-256）。
5. **恢复** —— 发布修复版本（可通过 `fuxi update` 获取）；验证受影响场景已
   恢复；解除临时缓解措施。对于凭据泄露事件，撤销并轮换受影响的令牌。
6. **复盘** —— 记录时间线、根本原因、影响与响应及时性；把改进纳入政策、标准
   与流程的修订。

### 1.4 通知与角色

- 若事件影响用户数据，我们依法并依承诺及时通知受影响用户与相关方；发生凭据
  泄露时，我们会给出补救建议（密钥轮换）；我们会发布必要的修复与缓解措施。
- **角色**：事件响应团队负责执行与遏制；安全负责人评定严重级别、作出决策并
  对外协调；法务/公关负责合规披露；工程团队交付根本原因修复与回归验证。

> 注：内部监控仅覆盖服务端的账号与发行基础设施。由于用户内容从不上传，我们
> 不监控 —— 也无法监控 —— 用户内容。

## 2. 漏洞披露

我们欢迎安全研究人员的报告。

- **报告渠道**：GitHub
  [安全通告](https://github.com/fuxicodex/Fuxi/security/advisories/new)
  （私下）。请勿在公开 issue 中讨论安全问题。
- **报告需包含**：FuXi 版本（`fuxi --version`）与安装方式；操作系统与 shell；
  最小复现步骤或概念验证；你评估的影响范围。
- **流程**：接收 → 确认（**3 个工作日内初次回复**）→ 分级 → 修复 → 协调披露
  → 公布。我们力求在细节公开前发布修复；披露窗口一般为确认与公开之间的最长
  **90 天**，若修复更快发布可缩短。
- **原则**：与报告者商定合理的公开时间线；在公开前不向无关方泄露细节；经报告
  者许可后致谢。
- **赏金**：FuXi 目前**没有**设立公开的漏洞赏金计划，也不公布奖励。若将来推出，
  其范围与奖励将正式公告。
- **对报告者的要求**：未经授权不得访问或泄露他人数据；不得实施拒绝服务、物理
  或社会工程攻击；遵守当地法律。

## 3. 第三方与供应链风险

| 类型 | 引入方 | 风险 |
|---|---|---|
| 模型提供商（BYOK） | 用户 | 内容传输、数据处理 |
| MCP 服务器 | 用户 | 工具访问、命令执行 |
| 插件 / 技能 | 用户 | 任意代码执行 |
| 供应商（托管、发行） | FuXi | 供应链、服务可用性 |

**你接入的第三方。** FuXi 如实说明哪些数据流向第三方，由你选择。MCP 服务器与
插件**默认关闭**，仅在你显式配置时才加载。请只从可信来源安装，并查阅每个第三
方的隐私政策与数据处理条款。

**FuXi 自身的供应链。** 安装与更新仅来自 `https://downloads.fuxicode.com`。
`fuxi update` 会对照已发布的 manifest 校验 SHA-256，并原子性地替换二进制。
单一静态二进制、无运行时依赖，缩小了供应链攻击面。产品源代码未公开，因此第三
方无法针对公开代码路径发起攻击；我们改为通过本文档体系、自检以及第 5 条的透明
度披露来提供可验证性。

**供应商评估。** 对于 FuXi 自身使用的第三方：只传输所必需的最少数据；评估其
安全与隐私做法；通过合同约束其数据处理；并予以披露（第 4 条）。发生第三方安全
事件时，我们评估用户影响并依承诺通知，同时迅速停用并清理不再使用或被认定有
风险的第三方。

## 4. 次级处理者

FuXi 是本地优先的：除下述账号与发行服务外，我们不聘请第三方处理用户数据，用户
内容也绝不由次级处理者处理。

| 处理者 | 用途 | 处理的数据 | 位置 |
|---|---|---|---|
| 官方发行/更新基础设施 | 分发二进制与更新 | 版本信息、基本的更新请求信息 | 以官网为准 |
| 账号认证服务（强制登录） | 身份认证与账号运营 | 账号标识 | 以官网为准 |

具体处理者清单与位置在官网（https://www.fuxicode.com）披露；清单如有重大变更，
会在生效前更新。

**明确排除。** 以下**不**属于 FuXi 的次级处理者（它们由你选择，而非由 FuXi
聘请）：你通过 BYOK 选择的模型提供商；你接入的 MCP 服务器；你安装的插件与技能。
它们的合规性由其各自政策约束。

## 5. 透明度与业务连续性

### 5.1 透明度披露

| 项目 | 状态 |
|---|---|
| 用户代码收集 | **无** —— 从不收集、存储或保留 |
| 对话内容收集 | **无** |
| 凭据收集 | **无** —— 仅存本地 |
| 隐藏遥测 | **无** —— 没有未披露的跟踪；存在的分析均已披露且可关闭（见[隐私控制](DATA_PROTECTION.zh-CN.md)） |
| 强制注册 | **是** —— 使用 FuXi 需要 FuXi 账号 |

政府与法律请求：我们只披露我们**实际持有**的内容。由于我们不持有用户代码或
对话，对于内容请求通常没有可披露的内容；账号信息请求仅在法律要求时、在我们持有
的最小范围内予以答复。当确有关请求发生时我们会公布数字；截至本版本，尚无相关
报告。

| 项目 | 状态 |
|---|---|
| 已报告的漏洞 | 通过仓库安全通告（私下；披露后公开） |
| 已确认的数据泄露 | 无公开记录 |
| 高严重级别事件 | 无公开记录 |

### 5.2 业务连续性

FuXi 的核心功能在你的设备上运行，因此一旦你已登录，我们服务的中断不会停止本地
工作。由于使用 FuXi 需要账号，账号系统中断可能阻断登录进而阻断使用 —— 但本地
数据始终安全地留在你的设备上。

| 服务 | 目标 | 说明 |
|---|---|---|
| 本地使用 | 独立于我们的服务 | 核心本地功能可离线/在我们服务中断期间使用 |
| 安装与更新服务 | 尽力而为 | 无正式的正常运行时间 SLA |
| 账号认证（必需） | 尽力而为 | 使用 FuXi 所必需 |

| 场景 | 用户影响 | 应对 |
|---|---|---|
| FuXi 服务器中断（发行/更新） | 已登录后本地任务工作不受影响 | 在本地继续工作；更新稍后恢复 |
| 用户设备故障 | 本地数据丢失 | 从你的备份恢复 |
| 分发渠道中断 | 无法安装/更新 | 改用备用官方渠道；及时恢复 |
| 账号系统故障 | 登录被阻断 → 使用被阻断 | 及时恢复；本地数据仍安全地留在设备上 |

### 5.3 备份与恢复

| 数据 | 位置 | 说明 |
|---|---|---|
| 配置与凭据 | `~/.fuxi/config.yaml`（或 `$FUXI_CONFIG_DIR/config.yaml`） | 提供商、模型、密钥 |
| 会话记录 | 配置目录下 | 历史、检查点 |
| 项目记忆 | 项目内的记忆文件 | 跨会话记忆 |
| 审计日志 | 配置目录下 | 操作记录 |
| 调试日志 | `~/.fuxi/logs/` | 诊断日志 |

```bash
# 备份配置目录
cp -a "$HOME/.fuxi" "$HOME/.fuxi.backup.$(date +%Y%m%d)"

# 恢复它
rm -rf "$HOME/.fuxi"
cp -a "$HOME/.fuxi.backup.<backup-date>" "$HOME/.fuxi"
fuxi doctor    # 恢复后验证
```

- **备份可能包含密钥** —— 请加密并安全存放。
- 若只需恢复单个会话，可在 TUI 中使用 `/history` 或 `/resume`，或在命令行使用
  `fuxi -r <sessionId>` / `fuxi -c`。

## 6. 责任

- **FuXi**：维护响应流程、如实披露、管理自身供应链，并以尽力而为的方式保持官方
  服务可用。
- **用户**：定义并执行你自己的备份（加密），并管理你所接入第三方的选择与风险。
