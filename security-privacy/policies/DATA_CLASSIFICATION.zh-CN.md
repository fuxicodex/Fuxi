# FuXi 数据分级分类政策

**Data Classification Policy**

*最后更新：2026-08-23 · 版本 1.0 · 层级：L1 政策*

本政策定义 FuXi 处理的数据类型、敏感度分级与相应的处理要求。

---

## 1. 分级体系

| 级别 | 定义 | 示例 | 处理要求 |
|---|---|---|---|
| **公开 Public** | 可公开的信息 | 文档、README、版本信息 | 无特殊要求 |
| **内部 Internal** | 运营所需、不宜公开 | 内部设计、度量数据 | 最小访问 |
| **敏感 Sensitive** | 泄露会造成风险 | 凭据、API Key、OAuth token | 加密存储、最小权限、禁止日志明文 |
| **用户内容 User Content** | 用户的代码与对话 | 源代码、提示词、会话 | 默认本地、不经服务器、由用户掌控 |

> **关键事实**：FuXi 的架构决定了**用户内容与凭据默认停留在用户设备**，
> 不进入 FuXi 的服务器。因此"敏感"与"用户内容"两类数据，FuXi 在服务器端
> **不持有**，这是最强的一层数据保护。

---

## 2. 各类型数据的处理位置

| 数据 | 存储位置 | FuXi 是否可访问 |
|---|---|---|
| 配置与凭据（config.yaml） | 用户本地 `~/.fuxi/` | 否 |
| 会话记录 | 用户本地 | 否 |
| 项目记忆文件 | 用户本地项目内 | 否 |
| 审计日志 | 用户本地 | 否 |
| 请求内容（BYOK 模式） | 用户 ↔ 提供商直连 | 否 |
| 登录账户信息（可选） | FuXi 账户系统 | 仅认证所必需 |

---

## 3. 处理规则

1. **禁止明文记录凭据**：任何日志、错误信息、截图均不得包含明文密钥。
2. **最小权限访问**：本地凭据文件建议设置仅用户可读的权限。
3. **加密建议**：建议用户启用全盘/文件系统加密保护本地数据。
4. **默认本地**：除非用户主动配置（登录、接入第三方），数据不出设备。
5. **脱敏**：在共享日志、issue、PR 前脱敏密钥与个人信息。

---

## 4. 数据生命周期

```
创建 → 使用 → 存储 → 归档/删除
        ↑ 用户全程掌控
```

- 本地数据的保留与删除由用户决定（删除 `~/.fuxi/` 即可）。
- 登录账户数据可在用户要求下删除。

---

## 5. 责任

- **安全团队**：维护本分级与对应的技术控制。
- **工程**：在功能设计中落实分级要求。
- **用户**：管理本地文件权限、磁盘加密与第三方选择。

---

*本政策确保所有数据按其敏感度得到恰当保护。*
